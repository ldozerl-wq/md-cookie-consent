# MD Cookie Consent — универсальный GDPR-баннер для сайтов Молдовы

Готовый к тиражированию комплект для Google Tag Manager на базе
[vanilla-cookieconsent v3.1.0](https://cookieconsent.orestbida.com/) (MIT).
Собственный **шаблон тега GTM**: подключение нового проекта — импортировать шаблон,
добавить тег и вписать в поле ссылку на политику. Ни строки кода на проект.

**Правовая база:** Закон РМ №195/2024 о защите персональных данных (в силе с **23.08.2026**,
штрафы до **2 000 000 леев или 2% годового оборота**) + Закон №284/2004 об услугах
информационного общества (именно он регулирует cookie) + Consent Mode v2 как требование Google.
Надзорный орган — **CNPDCP** (datepersonale.md).

## Установка — шаблон тега (основной путь)

### Шаг 0. Один раз: выложить рантайм

Шаблон работает в песочнице GTM без доступа к DOM, поэтому отрисовка баннера живёт
в отдельном файле. **Один файл обслуживает все проекты** — выложите его один раз.

**Уже сделано** — рантайм лежит в [github.com/ldozerl-wq/md-cookie-consent](https://github.com/ldozerl-wq/md-cookie-consent)
и раздаётся через jsDelivr:

```
https://cdn.jsdelivr.net/gh/ldozerl-wq/md-cookie-consent@v15/md-cookie-consent.js
```

Этот URL уже стоит в шаблоне значением по умолчанию — поле трогать не нужно.

Тег в URL фиксирует версию: правки в репозитории не поедут на прод сами по себе.
Обновление — новый тег и смена URL в поле шаблона (см. «Обновление версии» ниже).

**Вариант со своим доменом:** положите файл рядом с сайтом
(`https://ваш-домен.md/assets/md-cookie-consent.js`) и добавьте этот домен
в правах шаблона: **Templates → ваш шаблон → Permissions → Injects scripts**.

### Шаг 1. Импорт шаблона в контейнер

**Templates → Tag Templates → New → ⋮ → Import** → выбрать `md-cookie-consent.tpl` → **Save**.

Повторяется для каждого контейнера. Дальше шаблон живёт внутри контейнера и обновлять
его нужно только при выходе новой версии.

### Шаг 2. Добавить тег и заполнить поля

**Tags → New → Tag Configuration → MD Cookie Consent (Legea 195/2024)**

| Параметр | Значение |
|---|---|
| Name | `Cookie Consent (MD)` |
| **Политика конфиденциальности** | `/politica-de-confidentialitate` — ссылка для этого проекта |
| URL файла `md-cookie-consent.js` | адрес из шага 0 |
| Advanced → Tag firing priority | `1000` |
| Advanced → Consent Settings | **No additional consent required** |
| Trigger | **Consent Initialization – All Pages** |

> Именно `Consent Initialization`, а не `All Pages` — иначе GA4 успеет отправить хит
> до установки Consent Mode в `denied`.

Остальные поля (язык, цвет, форма баннера, вес кнопок, срок хранения, журнал согласий)
имеют рабочие значения по умолчанию — трогать их не обязательно.

**Всё. Подключение следующего проекта = шаги 1–2, одна ссылка в поле.**

> Поле обязательное — GTM не даст сохранить тег с пустым значением. Но если
> подставить туда переменную, которая в рантайме вернёт пустоту, баннер откатится
> на путь по умолчанию и напишет об этом `warning` в консоль. Ссылка при этом
> останется видимой, поэтому битый URL глазами не отличить — проверяйте кликом.

### Шаг 3. Заблокировать существующие теги

Два способа, можно комбинировать.

**А. Встроенные Consent Checks (рекомендуется для Google-тегов).**
Открыть тег → Advanced Settings → Consent Settings → *Require additional consent for tag to fire*:

| Тег | Требуемое согласие |
|---|---|
| GA4 Configuration / Events | `analytics_storage` |
| Google Ads Conversion / Remarketing | `ad_storage`, `ad_user_data`, `ad_personalization` |
| Floodlight | `ad_storage`, `ad_user_data` |
| Meta Pixel, TikTok, LinkedIn Insight | `ad_storage`, `ad_user_data`, `ad_personalization` |
| Hotjar, Clarity, Yandex.Metrica | `analytics_storage` |
| YouTube-эмбеды, чаты, карты | `functionality_storage` |

**Б. Триггеры по событиям (для не-Google тегов и Custom HTML).**
Рантайм пушит в dataLayer:

| Событие | Когда |
|---|---|
| `cookie_consent_update` | при любом выборе + при восстановлении сохранённого |
| `cc_analytics_granted` | согласие на аналитику |
| `cc_marketing_granted` | согласие на маркетинг |
| `cc_functional_granted` | согласие на функциональные |

Создать триггер *Custom Event* → `cc_marketing_granted` и повесить на Meta Pixel и т.п.

Дополнительно доступны переменные dataLayer:
`consent_id`, `consent_timestamp`, `consent_language`, `consent_revision`,
`consent_policy_version`, `consent_action`, `consent_necessary`, `consent_functional`,
`consent_analytics`, `consent_marketing`, `consent_source`.

### Шаг 4. Скрипты вне GTM

Всё, что вставлено прямо в шаблон сайта, тоже должно ждать согласия:

```html
<script type="text/plain" data-category="analytics" src="https://example.com/analytics.js"></script>

<script type="text/plain" data-category="marketing">
  /* код пикселя */
</script>

<iframe data-category="functional" data-src="https://www.youtube.com/embed/XXXX"></iframe>
```

`type="text/plain"` обязателен — без него браузер выполнит скрипт до согласия.

### Шаг 5. Ссылка «Настройки cookie» в футере

Плавающая кнопка включена галочкой в шаблоне. Если хотите вместо неё обычную ссылку
в футере — снимите галочку «Плавающая кнопка» и добавьте на сайт:

```html
<a href="#" data-cc="show-preferencesModal">Setări cookie</a>
```

Атрибут `data-cc` работает на любом элементе, JS писать не нужно.
Одно из двух должно быть обязательно: без постоянной точки отзыва согласия
требование закона не выполняется.

## Установка без хостинга (запасной путь)

Если выложить `md-cookie-consent.js` некуда, тот же баннер ставится двумя тегами
Custom HTML. Минус: настройки задаются не полями, а переменной GTM.

1. **Variables → New → Custom JavaScript**, имя `CC Config` — содержимое
   `gtm-variable-cc-config.js`, заполнить блок `SITES` доменами проектов.
2. **Tags → New → Custom HTML**, `gtm-tag-1-consent-default.html`,
   приоритет `1000`, триггер **Consent Initialization – All Pages**.
   В начале тега раскомментировать `window.MDCC_CONFIG = {{CC Config}};`.
3. **Tags → New → Custom HTML**, `gtm-tag-2-banner.html`,
   приоритет `900`, триггер **Initialization – All Pages**.

Дальше — шаги 3–5 выше, они одинаковы для обоих путей.

## Настройки на сайт

При основном пути — поля шаблона в интерфейсе GTM. При запасном — ключи в `SITES`
внутри `{{CC Config}}` или `window.MDCC_CONFIG` на самом сайте. Названия совпадают.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `privacyUrl` | `/politica-de-confidentialitate` | Единственная ссылка баннера. Если не задать — откат на дефолт + `warning` в консоли |
| `policyVersion` | `'1.0'` | Версия политики — пишется в журнал согласий |
| `revision` | `1` | **++ при изменении политики** → у всех запрашивается согласие заново |
| `defaultLang` | `'ro'` | `ro` / `ru` / `en` |
| `autoDetect` | `'document'` | `document` (по `<html lang>`), `path` (по префиксу адреса), `browser`, или `false` |
| `layout` | `'box wide'` | `box`, `box wide`, `box inline`, `cloud`, `bar`, `bar inline` |
| `position` | `'bottom left'` | Положение баннера |
| `accent` | `#2b6cb0` | Цвет главной кнопки и тумблеров |
| `buttonBias` | `'stacked'` | `stacked` — столбиком: «Принять все необязательные» и «Принять только необходимые» одного веса, серая «Настроить». `accept-first` — серый отказ, акцентное согласие у правого края. `equal` — родной ряд одного веса. См. раздел ниже |
| `floatingBtn` | `true` | Плавающая кнопка отзыва согласия |
| `floatingSide` | `'left'` | `left` / `right` (справа обычно чат — лучше слева) |
| `blockPage` | `false` | `true` = блокировать взаимодействие со страницей до выбора |
| `compactMobile` | `true` | RU/EN на экранах до 640px — короткая фраза + «Подробнее» вместо длинного абзаца (иначе абзац становится LCP страницы на телефоне). RO короткий всегда |
| `cookieDays` | `182` | Срок хранения согласия, дней (не более 12 мес.) |
| `logEndpoint` | `''` | URL для серверного журнала согласий (POST JSON) |
| `cdnBase` | jsDelivr | Заменить при самохостинге библиотеки |

### `buttonBias` — визуальный вес кнопок

#### `stacked` — по умолчанию с v11

Три кнопки столбиком во всю ширину карточки:

```
┌────────────────────────────┐
│ Принять все необязательные │  акцентная
├────────────────────────────┤
│ Принять только необходимые │  такая же акцентная
├────────────────────────────┤
│         Настроить          │  серая
└────────────────────────────┘
```

Согласие и отказ совпадают по цвету, размеру и весу шрифта, отказ стоит прямо
под согласием. Требование «отказаться не сложнее, чем согласиться» выполняется
буквально. Приглушена **настройка**, а не отказ — этого EDPB не запрещает:
ограничение касается выделения кнопки согласия на фоне отказа.

Тот же принцип в окне настроек, но в ряд: `Принять все необязательные`
и `Принять только необходимые` акцентные слева, серая `Сохранить выбор` отделена и прижата к правому краю.
Кнопки по содержимому, а не растянуты на треть ширины каждая — иначе
«Сохранить» перестаёт читаться как отдельное действие.

У серых кнопок фон светлый, но текст тёмный (контраст 10:1) и того же веса,
что у акцентных: со светло-серой надписью кнопка выглядит неактивной.

Порядок узлов в DOM у библиотеки изначально такой, переставлять ничего не нужно —
обход по Tab совпадает с тем, что видит глаз.

На телефоне карточка выше, чем полоса из `accept-first` (три кнопки по 44px
друг под другом). Если для конкретного клиента критична высота первого экрана —
смотрите `accept-first` с раскладкой `bar`, см. ниже.

#### `accept-first` — конверсия в обмен на риск

```
[ Настроить ] [ Принять только необходимые ]  ·····  [ Принять все необязательные ]
   обычная                 серая                              акцентная
```

На мобильном ряд превращается в столбец: настроить → только необходимые → все необязательные.
«Принять все» оказывается внизу, ближе всего к большому пальцу. С раскладкой
`bar` на телефоне кнопки встают в один ряд, а баннер занимает ~25% экрана
вместо ~46% (см. v7–v9).

Узлы переставляются в DOM (`biasButtons()` в рантайме), а не через CSS `order`,
поэтому обход по Tab совпадает с визуальным порядком.

> ⚠️ **Правовой риск.** Непропорциональное выделение кнопки согласия — это deceptive design
> по EDPB Guidelines 03/2022 (раздел о «highlighting» и «visual interference»). Требование
> «отказаться не сложнее, чем согласиться» формально нарушается не порядком кнопок,
> а разницей в цветовом контрасте. При проверке CNPDCP согласие, собранное таким баннером,
> может быть признано недействительным со всеми последствиями — включая штраф
> до 2 000 000 леев или 2% годового оборота и обязанность удалить собранные данные.
>
> Порядок «принять слева, отказаться справа» сам по себе законен. Рискует именно серый цвет.

#### `equal` — равнозначные в один ряд

Родной горизонтальный ряд библиотеки, все кнопки одного оформления.
Вариант для тех, кому нужен ряд, а не столбик.

Решение принимается по каждому сайту отдельно — переключатель для того и сделан.

### Многоязычные сайты

Ставьте корректный `<html lang="ro">` / `lang="ru"` — при `autoDetect: 'document'`
баннер сам подхватит язык страницы. `lang="mo"` и `lang="md"` мапятся на румынский.

Региональные коды тоже работают: `ru-RU`, `en-GB`, `ro-MD` — регион срезается.
Если сайт меняет язык без перезагрузки страницы, достаточно поменять `<html lang>` —
баннер и подпись плавающей кнопки переключатся сами. Вызов
`CookieConsent.setLanguage('ru-RU')` из кода сайта тоже допустим.

### Когда `<html lang>` в шаблоне неверный

Встречается регулярно: шаблон отдаёт один и тот же `lang` на всех языковых
версиях, и румынская страница объявляет себя русской. Баннер читает разметку
и честно показывает не тот язык.

**Правильное решение — починить шаблон сайта.** Неверный `lang` ломает не только
баннер: поисковики и скринридеры тоже читают текст как чужой язык. В Joomla
это строка в `index.php` шаблона:

```php
<html lang="<?php echo $this->language; ?>" dir="<?php echo $this->direction; ?>">
```

**Если шаблон править нельзя**, поставьте `autoDetect: 'path'` — язык берётся
из первого сегмента адреса (`/ro/`, `/ru/`, `/en/`), разметка игнорируется.
Язык корня сайта без префикса задаёт `defaultLang`. Сегмент должен выглядеть
как код языка, поэтому `/romania/` за румынский не примется.

## Журнал согласий

Требование закона: каждое действие фиксируется отдельной записью с меткой времени,
языком, выбранными категориями и версией политики; записи не перезаписываются.

**Клиентская сторона** — `localStorage.mdcc_consent_log`, до 50 последних записей:

```js
MDCC.log()
// [{id, ts, lang, rev, pv, act, cats, url}, ...]
```

**Серверная сторона** — задайте `logEndpoint`, и на него уйдёт `POST application/json`
(через `sendBeacon`) с полями `consent_id`, `timestamp`, `language`, `revision`,
`policy_version`, `action`, `categories`, `page`, `user_agent`.

> Для полноценного доказательства согласия при проверке CNPDCP серверный журнал
> обязателен — localStorage пользователь может очистить. Храните записи столько же,
> сколько действует согласие, + срок исковой давности.

## Публичный API на странице

```js
MDCC.show()              // открыть настройки
MDCC.reset()             // стереть согласие и перезагрузить (для тестов)
MDCC.log()               // журнал согласий
MDCC.accepted('marketing') // true/false

CookieConsent.setLanguage('ru')
CookieConsent.acceptedCategory('analytics')
CookieConsent.showPreferences()
```

## Соответствие требованиям

| Требование | Как закрыто |
|---|---|
| Скрипты не грузятся до согласия | `mode: 'opt-in'` + `manageScriptTags` + Consent Mode `denied` в Теге 1 |
| Три кнопки на первом экране | `Setări` / `Refuz toate` / `Accept toate` — все три видны без прокрутки и без доп. кликов |
| «Отказаться не сложнее, чем согласиться» | ✅ При `buttonBias: 'stacked'` (по умолчанию с v11) отказ — такая же кнопка того же цвета и размера прямо под согласием. ⚠️ При `accept-first` отказ серый, а согласие акцентное: риск по EDPB, см. раздел выше |
| 4 категории | necessary (readOnly) / functional / analytics / marketing |
| Гранулярность | Отдельный тумблер на каждую необязательную категорию: любую можно принять или отклонить независимо от остальных |
| Нет преднажатых галочек | `enabled: false` у всех необязательных категорий |
| Отзыв согласия в любой момент | Плавающая кнопка + `data-cc="show-preferencesModal"` |
| Удаление cookie при отказе | `autoClearCookies: true` + regex-списки по каждой категории |
| Информирование | По каждому cookie в окне настроек: название, назначение простым языком, поставщик со ссылкой на его политику защиты данных, срок хранения, трансграничная передача |
| Оператор и контакты | ⚠️ **В баннере не выводятся** — только в политике конфиденциальности. Ссылка на неё есть и на первом слое, и в окне настроек |
| Трансграничная передача | Колонка «Передача» в таблице каждой категории: страна по каждому cookie отдельно, «Без передачи» у собственных cookie сайта |
| Права субъекта + CNPDCP + 1 месяц | ⚠️ **В баннере не выводятся** — политика конфиденциальности, все три языка |
| Журнал согласий | `mdcc_consent_log` + `logEndpoint` + `consent_id` + `policy_version` |
| Версионирование политики | `revision` → повышение форсирует пересогласие |
| Все языки витрины | RO / RU / EN, автоопределение по `<html lang>` |
| Отдельная страница Политики Cookie | ⚠️ **Из баннера не ссылается.** Страница по закону обязательна — опубликуйте по `cookie-policy-template.md` и дайте ссылку на неё из политики конфиденциальности |
| Consent Mode v2 | `ad_user_data` + `ad_personalization` + `ads_data_redaction` + `url_passthrough` |

## Что остаётся сделать вручную

1. **Опубликовать политику конфиденциальности** на каждом языке и вписать её URL
   в поле тега. Это единственная ссылка баннера и единственное место, где
   раскрываются реквизиты оператора, права субъекта данных и порядок обращения
   в CNPDCP. Проверьте её кликом: битый URL выглядит так же, как рабочий.
2. **Опубликовать страницу политики cookie** (шаблон — `cookie-policy-template.md`)
   на каждом языке и **дать на неё ссылку из политики конфиденциальности**.
   Из баннера она больше не ссылается, но по закону остаётся обязательной.
3. **Сверить таблицы cookie** в `md-cookie-consent.js` с реальным набором на сайте
   (DevTools → Application → Cookies после принятия всех категорий). Лишние строки убрать, недостающие добавить.
   Каждая строка обязана содержать пять полей: название, назначение простым языком, поставщика
   со ссылкой на его политику, срок хранения и страну трансграничной передачи.
4. **Проверить поставщиков и страны передачи.** В `PROVIDERS` стоят узнаваемые торговые названия
   (Google Analytics, Meta, TikTok) и ссылки на их публичные политики, в колонке «Передача» — США
   как страна обработки. Договаривающееся юрлицо и страна зависят от конкретного DPA клиента:
   если договор с европейским юрлицом, поправьте и название, и страну. Выдумывать юрлицо за клиента нельзя.
   У собственных cookie сайта стоит «Без передачи» — проверьте, что хостинг действительно в стране оператора.
5. **Проверить `autoClear`-списки** — добавить cookie ваших сервисов, чтобы отказ реально их стирал.
6. **Заключить DPA** с обработчиками (Google, Meta, хостинг, CRM) и отразить их в политике.
7. **Настроить серверный `logEndpoint`** и хранение журнала.
8. Уведомительные/регистрационные обязанности перед CNPDCP — по профилю обработки; вопрос к юристу.

> Комплект закрывает техническую часть. Юридическую оценку конкретной обработки
> (правовые основания, DPIA, назначение DPO, регистрация) он не заменяет.

## Тестирование

```bash
python -m http.server 8777 --directory md-cookie-consent
```

Стенд показывает состояние Consent Mode, категории, события dataLayer, журнал согласий
и скрипт, заблокированный до согласия на аналитику.

| URL | Что проверяет |
|---|---|
| `http://localhost:8777/test.html` | Основной путь: `MDCC_CONFIG` со строковыми значениями (как их отдаёт шаблон GTM) + рантайм отдельным файлом |
| `…/test.html?cdn=1` | Продовый путь целиком: рантайм тянется с jsDelivr по тому же URL, что стоит в шаблоне |
| `…/test.html?inline=1` | Запасной путь: сгенерированный Custom HTML тег |
| `…/test.html?bias=accept-first` | Прежний вариант: серый отказ, акцентное согласие справа |
| `…/test.html?bias=equal` | Равнозначные кнопки в один ряд |
| `…/test.html?lang=ru-RU` | Язык с регионом в `<html lang>` |
| `…/ro/` | `autoDetect: path` при неверном `<html lang="ru-RU">` |

Чек-лист перед публикацией:

- [ ] До выбора: в DevTools → Application → Cookies нет `_ga`, `_fbp`, `_gcl_*`
- [ ] «Принять только необходимые» → cookie не появляются, `analytics_storage: denied` в GA4 debug
- [ ] «Принять все необязательные» → теги срабатывают, в Tag Assistant виден `consent update`
- [ ] Отказ после согласия → старые cookie удаляются (`autoClear`)
- [ ] Плавающая кнопка открывает настройки на всех языках
- [ ] `<html lang>` меняет язык баннера, включая коды с регионом (`ru-RU`)
- [ ] `revision: 2` → баннер показывается заново уже согласившимся
- [ ] Google Tag Assistant → вкладка Consent: все 7 сигналов присутствуют
- [ ] Preview-режим GTM: тег шаблона сработал на Consent Initialization, ошибок в консоли нет
- [ ] Ссылки из полей тега открываются, а не ведут на 404

## Обновление версии

Рантайм зафиксирован тегом в URL (сейчас `@v15`), поэтому правки в репозитории
не уезжают на прод сами. Порядок обновления:

1. Правки — только в `md-cookie-consent.js`.
2. `powershell -File build.ps1` — пересобрать inline-тег.
3. Новый тег в репозитории (`v3`, `v4`, …). Старые теги не перевешиваются.
4. Обновить URL в `md-cookie-consent.tpl`, `README.md`, `test.html`.
5. В контейнерах: переимпортировать шаблон **или** вручную поменять URL
   в поле «URL файла md-cookie-consent.js» у уже добавленных тегов —
   значение по умолчанию подставляется только при создании тега.

Шаблон `.tpl` переимпортируется, если менялись поля, код песочницы или URL по умолчанию.

### История версий

| Тег | Что изменилось |
|---|---|
| `v1` | Первый релиз |
| `v2` | Порядок кнопок первого слоя: `[Настройки] [Отклонить] ··· [Принять]` |
| `v3` | Одна ссылка вместо двух: убрана политика cookie, оставлена конфиденциальность. Ключ `cookieUrl` и поле «Политика Cookie» удалены. Предупреждение в консоли, если `privacyUrl` не задан |
| `v4` | **Исправлена плавающая кнопка отзыва согласия.** Она не открывала настройки, а вернувшемуся посетителю не показывалась вовсе — то есть постоянной точки отзыва на сайте фактически не было. Обновление обязательное для всех контейнеров, где стоит `v1`–`v3` |
| `v5` | **Языки с регионом (`ru-RU`, `en-GB`).** `setLanguage('ru-RU')` в самой библиотеке молча ничего не делал — теперь регион срезается до вызова. Подпись плавающей кнопки следует языку страницы, а не языку, на котором когда-то дали согласие. Смена `<html lang>` на лету подхватывается (SPA, переключатель языка без перезагрузки) |
| `v6` | Режим `autoDetect: 'path'` — язык по префиксу адреса (`/ro/`, `/ru/`) для сайтов, где шаблон отдаёт неверный `<html lang>` на всех языковых версиях. Требует переимпорта шаблона: появилось новое значение в поле «Определять язык автоматически» |
| `v7` | Компактный баннер для телефона: RO — короткий текст «Folosim cookie-uri» со ссылкой на политику прямо в тексте, кнопки «Refuz» / «Setări». Раскладка `bar` (полоса внизу) на экранах до 640px: «Refuz» и «Accept toate» в один ряд, «Setări» ссылкой над ними. Раскладка по умолчанию не изменена — полоса включается полями `layout = 'bar inline'`, `position = 'bottom'` |
| `v8` | Кнопки полосы в один ряд на телефоне действительно работают (селекторы усилены, `!important` — `cookieconsent.css` грузится позже и перебивал стили) |
| `v9` | В полосе на компьютере убран дубль ссылки на политику (подвал скрыт — ссылка уже в тексте) |
| `v10` | **Компактный первый слой RU/EN на телефонах** (`compactMobile`, по умолчанию включён): на экранах до 640px короткая фраза + «Подробнее» раскрывает полный текст; на компьютере текст прежний. Длинный абзац появлялся поздно (после GTM) и на телефоне был самым крупным текстом экрана — PageSpeed засчитывал его как LCP (на paradis.md ~9 с). RO короткий на всех экранах с v7. Переимпорт шаблона не обязателен: без поля действует значение по умолчанию; переимпорт добавляет флажок, чтобы выключить режим для конкретного клиента |
| `v11` | **Новый вид кнопок — `buttonBias: 'stacked'`, теперь значение по умолчанию.** Первый слой: `Принять все` и `Отклонить все` одного веса столбиком во всю ширину, ниже серая `Настроить`. Окно настроек — по тому же принципу, `Сохранить выбор` серая. Требование «отказаться не сложнее» выполняется буквально. Попутно: ссылка на политику в описании раздела настроек больше не прилипает к предыдущему предложению. **Уже добавленные теги сохраняют свой `accept-first`** — значение по умолчанию подставляется только при создании тега, меняйте поле вручную |
| `v12` | **Раскрытие по каждому cookie: пять полей** — название, назначение простым языком, поставщик **со ссылкой на его политику защиты данных**, срок хранения, **страна трансграничной передачи**. Кнопка «Принять все» переименована в «Принять все необязательные» (`Accept toate nenecesare` / `Accept all non-essential`) — на первом слое и в окне настроек. Требования со встречи по cookie |
| `v13` | Кнопки доведены до образца: у серых («Настроить», «Сохранить выбор») текст тёмный вместо светло-серого — кнопка больше не выглядит неактивной. В подвале настроек «Принять все» и «Отклонить все» стоят парой слева, серая «Сохранить выбор» отделена и прижата вправо; ширина по содержимому, а не поровну на три |
| `v14` | **Названия кнопок приведены к образцу заказчика** (point.md): вторая кнопка первого слоя — `Принять только необходимые` / `Accept doar necesare` / `Accept only essential` вместо `Отклонить все`. Одно и то же название теперь на первом слое и в настройках — раньше румынская кнопка называлась `Refuz` на баннере и `Refuz toate` в настройках. Заголовок RU: «Мы ценим вашу конфиденциальность». Текст баннера переписан под новые названия |
| `v15` | Ссылка на политику в румынском первом слое выводилась дважды — в тексте и в подвале. Из текста убрана, подвал остался единственным местом. Заодно снято правило v9, прятавшее подвал в раскладке `bar`: оно существовало ровно из-за этого дубля, а без него в полосе не осталось бы ссылки вообще |

## Самохостинг библиотеки cookieconsent

Зависимость от jsDelivr — точка отказа и внешний запрос. Для продакшена скачайте
`cookieconsent.umd.js` и `cookieconsent.css` из
`https://cdn.jsdelivr.net/npm/vanilla-cookieconsent@3.1.0/dist/`, положите рядом
с рантаймом и поменяйте `cdnBase` в `DEFAULTS` внутри `md-cookie-consent.js`
(отдельным полем шаблона это не вынесено — настройка разовая, на все проекты сразу).

Рантайм ничего не грузит до `DOMContentLoaded` и не блокирует рендер (`defer`),
вес — ~30 КБ gzip.
